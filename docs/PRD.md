# L-Sync PRD (제품 요구사항 정의서)

**목적:** 프로젝트의 비전, 정책, 마일스톤을 정의하여 개발 중 흔들리지 않는 의사결정 기준을 제공.

---

## 1. 프로젝트 비전 및 원칙

- **제품명:** L-Sync (Life-Synchronization)
- **비전:** 일정, 할 일, 재정, 신앙을 하나의 흐름으로 동기화하는 개인 맞춤형 안드로이드 생산성 허브.
- **핵심 원칙:**
  - **Offline-First:** 모든 핵심 기능은 네트워크 단절 시에도 100% 동작해야 한다.
  - **지속 가능한 페이스:** 번아웃 방지를 위해 측정 가능하고 합리적인 단계별 검증(Dogfooding)을 거친다.
  - **데이터 영속성 보장:** 사용자 편의를 위한 삭제 기능(Todo 삭제 등)이 과거의 자산 기록(가계부)을 훼손해서는 안 된다.

---

## 2. 핵심 도메인 정책

### 2.1. 시간대(Timezone) 정책

- **종일 일정 & 마감일 Todo:** Floating Time 적용. 기기 시간대와 무관하게 저장된 '날짜 문자열' 그 자체를 기준으로 렌더링.
- **시간 지정 일정:** 한국 시간(UTC+9) 기준으로 저장하되, 해외 출장 시를 대비해 '타임존 고정(Timezone Lock)' 옵션을 제공.

### 2.2. Todo ↔ 가계부 생명주기 정책

- Todo 완료 시 가계부 데이터 자동 생성. (금액 미정 시 UI 팝업 강제)
- Todo 미완료(Uncheck) 시 연결된 가계부 데이터는 통계에서만 제외(Soft Delete).
- Todo 삭제 시 가계부 데이터는 유지되며 연결 고리(`sourceTodoId`)만 해제.

### 2.3. 반복 Todo 정책 (가계부 연동용)

- 서버 의존도를 낮추기 위해 **'Client-side Materialization'** 적용.
- 사용자가 템플릿을 만들면, 앱이 백그라운드에서 주기적으로 개별 Todo 문서들을 생성.
- **템플릿 생성 UI:** 일정 화면의 반복 할 일 FAB → 빈도(매일/매주/매월)·간격(N주마다 등)·요일·가계부 연동을 선택하면 `buildRrule`이 RRULE 문자열을 만들고 템플릿을 저장. 활성 템플릿은 목록에서 확인·중지(deactivate) 가능.
- **인스턴스 생명주기 일원화:** Materializer가 만든 개별 인스턴스도 단발성 Todo와 동일하게 Room 저장 + Firestore 동기화 + 마감일 알람 등록을 거친다(`TodoRepository.upsertMaterialized`). 템플릿 생성 직후 `MaterializationTrigger`로 1회 즉시 생성한다.

### 2.4. 정산(Settlement) 정책

- 공동 결제 후 일부 금액을 돌려받는 흐름을 추적. 별도 테이블 없이 `settlementGroupId` 단일 컬럼으로 그룹화(EXPENSE 리더 + INCOME 정산 입금).
- 정산 입금은 **실제 수입이 아니므로 수입·지출 통계에 합산하지 않고** 별도 집계한다. 잔액(`net`)에는 정확히 반영(`net = income + reimbursed − expense`).
- 정산 리더(EXPENSE) 삭제 시 그룹 전체 정리. 단 데이터 영속성 정책상 Todo 연동 입금은 삭제하지 않고 연결만 해제.

### 2.5. 반복 일정 정책 (iCal 읽기-전개)

- 반복 일정은 **마스터 한 행만 저장하고 발생(occurrence)은 런타임에 전개**한다(읽기-전개). 별도 인스턴스를 미리 생성하지 않아 저장 비용·동기화 부담을 줄인다(반복 Todo의 materialization과 대비되는 전략).
- 발생별 예외는 `exdatesJson`(제외)·`overridesJson`(수정)로 표현. 삭제·수정은 **단건 / 이후 전체 / 시리즈 전체** 세 범위를 제공한다.

### 2.6. 예산 정책 (가계부 월 한도)

- 카테고리별 한도와 **전체 월 한도**(`__TOTAL__`)를 설정할 수 있으며 **매월 반복** 적용한다.
- 카테고리 예산은 해당 카테고리 EXPENSE 원금, 전체 예산은 **순지출**(`expense − reimbursed`)을 사용량으로 본다(정산 정책 2.4와 일관).
- 한도 초과 시에만 경고 색을 노출한다(절제된 시각 표현 = 디자인 의도).

### 2.7. 계정 전환 데이터 격리 정책

- 로그아웃 시 동기화 대상 데이터(events·todos·finance·budgets·todo_templates)는 로컬에서 정리해 **다른 계정으로 전환할 때 이전 사용자 데이터가 노출되지 않게** 한다. 알람도 함께 선취소한다.
- 단 **로컬 전용·복원 불가 데이터(통독 진행 `reading_plan`, 묵상 메모 `memos`)는 보존**한다(Firestore 미동기화라 다시 받을 수 없음).

### 2.8. 리마인더 알림 정책 (통독 · 소비)

- 앱을 열지 않아도 오늘 통독 잔여 분량과 소비 현황이 도달하도록 **정기 리마인더** 3종(통독 매일 / 소비 매일 / 소비 주간)을 제공한다. 각각 독립 on/off + 시각 설정.
- **기본값은 전부 off.** 사용자가 켜지 않은 알림이 앱 업데이트만으로 울려서는 안 된다.
- **잔소리 금지:** 오늘 통독 분량을 이미 다 읽었으면 알림을 보내지 않는다. 통독 미시작·완주 상태도 마찬가지.
- 주간 소비 집계는 **최근 7일 vs 직전 7일**로 잡는다. 사용자가 어떤 요일을 골라도 구간 길이가 같아 비교가 성립한다.
- 로그아웃 상태에서는 소비 알림만 조용히 건너뛴다(다음 회차 등록은 계속). 통독 진행은 로컬 전용(2.7)이라 로그인과 무관하게 동작한다.
- 알림 설정은 **기기별 로컬 설정**이며 Firestore 동기화 대상이 아니다.

### ✅ Phase 5: Firebase Auth Google 로그인 — 완료

- **구현:** Google 로그인 화면, Firebase Auth 연동, `userId = "local_user"` 하드코딩 전면 교체, 기존 Room 데이터 자동 마이그레이션, 홈 화면 로그아웃 메뉴.

- **Firestore 보안 규칙:** `request.auth.uid == resource.data.userId` 적용. 기존 `"local_user"` Firestore 데이터는 폐기 후 마이그레이션된 UID로 재동기화.

### ✅ Phase 6: 통독 고급화 — 완료

### ✅ Phase 20: 리포트 위젯 + 집계 단일화 — 완료

- **구현:** 별도 4×2 Glance 위젯(이번 달 완료율·일정 발생 수·순지출·통독), 탭 시 리포트 화면 딥링크.
- **집계 단일 출처:** `data/report/MonthlyAggregate.kt` 신설. **새로 집계가 필요한 곳은 반드시 이것을 호출한다** — 사본이 늘면 화면마다 숫자가 갈라진다(Phase 17에서 실제 발생). 기존 검증 완료 사본 3곳은 회귀 위험 때문에 의도적으로 남겼다.

### ✅ Phase 21: 리포트 내보내기 — 완료

- **구현:** 월간 리포트를 이미지(PNG)·텍스트로 공유. 화면의 카드 Composable을 그대로 오프스크린 렌더하고, 텍스트 요약은 집계를 다시 하지 않고 화면 상태를 그대로 소비한다.
- **실패 대응:** 이미지 렌더는 어디서든 실패할 수 있으므로 항상 텍스트 공유 대안을 제시한다.

### ✅ Phase 22: 정기 리마인더 (통독 · 소비 요약) — 완료

- **구현:** 통독 리마인더(매일)·소비 요약(매일 + 주간) 알림. 홈 메뉴 → 알림 설정 화면에서 개별 on/off·시각·요일 지정(정책 2.8).
- **엔진:** `ReminderScheduler`(트리거 시각 단일 계산, 순수 함수 + 단위 테스트) → AlarmManager → `ReminderReceiver`(내용 계산·게시·다음 회차 재무장). 채널 2개 분리(통독=소리, 소비=무음).
- **복원:** 발화 시 재무장 + 앱 시작 `syncAll()` + `AlarmRestoreWorker`(재부팅·`MY_PACKAGE_REPLACED`) 3중화.
