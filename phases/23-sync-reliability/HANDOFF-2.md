# 작업 지시 (후속): `원본 없음` 로그가 영원히 해소되지 않는 문제

**이것은 새 작업 요청이다.** 직전 커밋 `0340086`은 정상 반영됐고 다시 확인할 필요 없다. 그 커밋의 검증에서 **새로 발견된 결함 1건**을 고쳐 달라.

기준 브랜치 `feat-23-sync-reliability` (HEAD = `0340086`). `main` 머지·push 금지, 기존 커밋 rewrite 금지, `Co-Authored-By` 줄 금지.

---

## 결함

`SyncRepository.markSourceMissing` 경로로 표시된 행(`errorType = 'SourceMissing'`)은 `success = 0`, `resolvedAt = NULL`로 남는다. 그런데 이 행을 해소할 경로가 **어디에도 없다.**

주된 발생 시나리오는 로그아웃으로 `clearLocalUserData()`가 로컬 테이블을 비운 뒤 원본이 사라진 경우다. **원본은 돌아오지 않는다.** 그 결과:

1. `hasUnresolvedFailures()`가 영구히 `true` → 워커가 매 실행마다 상한 5회(30초→4분 지수 백오프)를 전부 소진한다. `LSyncApplication.onCreate()`의 안전망 트리거 때문에 **앱을 켤 때마다 반복**된다. 재전송할 수 있는 것이 하나도 없는데도
2. 가지치기가 미해결 실패를 보존하도록 바뀌었으므로 이 행은 **30일이 지나도 삭제되지 않는다** — 무기한 누적
3. 화면의 "미해결 실패" 건수가 0으로 돌아가지 않고, 사용자가 치울 수단이 없다(삭제 버튼은 의도적으로 두지 않았다)

`docs/TechSpec.md` §12.3의 *"원본이 복구되면 다음 재시도에서 해소할 수 있다"*는 원본이 복구되는 경우에만 맞고, 주 시나리오를 다루지 못한다.

## 요구 계약

1. **워커의 계속-재시도 판정에서 `SourceMissing`을 제외한다.** `hasUnresolvedFailures()`(또는 그 자리에서 쓰는 판정)가 재전송으로 해소될 가능성이 있는 실패만 세도록 바꾼다. 재시도해봐야 네트워크 호출조차 없는 행 때문에 워커가 백오프를 소진하면 안 된다
2. **`getUnresolvedFailures()`(재전송 대상 목록)에서는 빼지 마라.** 원본이 돌아오는 경우(pull 복원 등)에 해소될 수 있어야 한다. Room 조회 1회뿐이라 비용도 없다
3. **화면의 미해결 건수에서도 빼지 마라.** 실제로 미해결이고 사용자가 무엇이 유실됐는지 볼 수 있어야 한다. 목록의 `원본 없음` 표시는 그대로 둔다
4. **보존 기간이 지난 `SourceMissing` 행은 가지치기 대상에 포함한다.** 30일이면 사용자가 확인할 시간으로 충분하고, 이 행은 영구 보존할 이유가 없다(재전송 불가). 이걸로 배지가 결국 0으로 돌아간다
5. `docs/TechSpec.md` §12.2~§12.4의 보존·해소 서술을 위 내용에 맞춘다. 버전은 v0.15 → **v0.16**

## 금지

- **삭제·초기화 버튼을 만들지 마라.** 게이트 측정 이력이 사용자 조작으로 리셋되면 판정이 무의미해진다
- **`AppDatabase` 버전을 올리지 마라.** 쿼리 조건만 바꾸면 되고 스키마 변경은 필요 없다
- 1절에서 이미 확정된 것(`syncSafe` 5벌, 재시도 경로 무로깅, `merge*` 단일 출처, KEEP 정책, 게이트 분모에서 pull 제외)은 그대로 둔다
